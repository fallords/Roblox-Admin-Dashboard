## 1. Architecture

A single Next.js application (monolith) with clear internal layers:

```
Browser ──HTTPS──> Next.js (App Router, Node.js runtime)
                   ├─ proxy.ts               CSP nonce, optimistic auth redirect
                   ├─ app/ (pages, Server Actions)
                   │    └─ every entry point calls the data-access layer
                   ├─ lib/auth, lib/permissions, lib/validation, lib/audit
                   ├─ lib/database  ──> Prisma 7 + better-sqlite3 adapter ──> SQLite file
                   └─ services/roblox ──> RobloxIntegration interface
                                          └─ Phase 1: UnavailableRobloxAdapter (always refuses)
```

- **Frontend:** React Server Components by default. Client components only for the login form
  (`useActionState`), active-link highlighting and the mobile drawer.
- **Backend:** Server Actions for mutations (login, logout). Services take the database client as
  a parameter, so they are tested against real SQLite.
- **Storage:** SQLite locally. Provider-specific code is limited to `src/lib/database/client.ts`
  and the Prisma `provider`. A move to Postgres or libSQL later changes those two places plus the
  migrations.
- **Data provenance is part of the model:** each game record has `source` = DEMO, MANUAL or
  ROBLOX, and the UI derives its Demo / Local DB / Live / Not connected badges from it.
- **Configuration versioning** (`ConfigVersion`: DRAFT → PENDING → ACTIVE) and the **command
  queue** (`AdminCommand` with idempotency key, correlation id, expiry) exist in the schema but
  have no code yet. They are designed now so later phases do not need to reshape data.

## 4. Security design (summary)

Full detail: [`security.md`](security.md).

- No registration. Accounts come from a server-side CLI; the first is OWNER, later ones VIEWER by
  default.
- argon2id passwords; uniform failure messages; timing equalized for unknown users.
- Throttling: 5 failures per username per 15 minutes (cannot be bypassed by spoofing IPs); per-IP
  limit only behind a trusted proxy.
- Opaque 256-bit session tokens, stored only as SHA-256. Cookie is `httpOnly`, `SameSite=Lax`,
  and `Secure`/`__Host-` in production. 2 h idle / 12 h absolute expiry. Revoked on
  deactivation or password change.
- RBAC with 15 permissions over 4 roles. Every page and action checks its own permission; denials
  are audited.
- CSP with per-request nonces, frame and clickjacking protection, HSTS in production, no-store
  caching.
- Append-only audit log, enforced by the application and by database triggers; details are
  redacted.
- Closed command set for Roblox; no arbitrary Lua. The adapter refuses everything until Phase 4
  is implemented and tested.
- A documented credential-revocation runbook and a pre-deployment checklist.
